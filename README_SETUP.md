# APIR APIR - Patintero Prototype

This Unity 6.3 project contains the first playable APIR APIR event: a four-human-player, server-authoritative Patintero prototype built with Netcode for GameObjects, Unity Transport, and the Unity Input System.

## Open and generate

1. Open this folder in Unity `6000.3.20f1`.
2. Let Unity Package Manager finish resolving packages and scripts.
3. If `Assets/Scenes/PatinteroPrototype.unity` is not present, run **Tools > APIR APIR > Build Patintero Prototype**. The committed scene is normally generated by the same builder during verification.
4. Open `Assets/Scenes/PatinteroPrototype.unity` and press Play.

The generator creates and assigns the settings asset, player prefab, NetworkManager, Unity Transport, scene NetworkObject, court, camera, UI, materials, and build scene entry. It is safe to run again; generated assets are replaced or updated in place.

## Four-player LAN run

1. On one computer or Unity instance, leave the address as `127.0.0.1`, keep port `7777`, and select **HOST**.
2. On each of three clients, enter the host computer's LAN IPv4 address (for example `192.168.1.20`), use the same port, and select **JOIN**.
3. For multiple clients on one machine, create a standalone development build or use Multiplayer Play Mode. The package is installed; create three virtual players from **Window > Multiplayer > Multiplayer Play Mode** if the Editor does not already have a virtual-player configuration.
4. The round starts automatically when exactly four players are connected. Player 1 is Taya for this prototype; Players 2-4 are Runners.
5. Use WASD or arrow keys. The Taya is server-restricted to the red line. Runners must touch the far yellow line and return to the blue line.
6. The host can select **RESTART ROUND** after the result. Any player can select **DISCONNECT**.

Windows Firewall may ask permission for the Editor or build to receive private-network traffic. Allow private/LAN access on the host. Local LAN play does not use Relay or require Unity Dashboard credentials.

For automated local smoke tests, a standalone player also accepts `--patintero-host` or `--patintero-client`. These flags use the UI's configured default endpoint (`127.0.0.1:7777`) and leave normal button-driven startup unchanged when no flag is supplied.

## Rules and tuning

All prototype values live in `Assets/APIRAPIR/Patintero/Config/PatinteroSettings.asset`:

- Court width and length
- Player radius and end-zone depth
- Guarding line positions
- Runner and Taya speeds
- Tag radius and input send rate
- Round duration, required players, and Taya count

The rules and spawn assignment already support one or two Taya and arbitrary configured guard-line positions. The current asset uses the requested 1v3 setup and 30-second timer.

## Authority model

- Clients sample local keyboard input and submit normalized movement intent.
- The server applies speed, court bounds, and Taya line constraints, then replicates transforms.
- The server alone advances runner crossing state, detects tags, expires the timer, decides results, and accepts restarts.
- Connection approval caps the session at four, uses a per-process token to reject duplicate connection attempts, and refuses late joins during active or completed rounds.
- A disconnected Taya yields a Runners win; disconnecting Runners are removed from active-runner evaluation. Host shutdown disconnects the session.

## Tests

Run **Window > General > Test Runner > EditMode > Run All**. The focused rule tests cover diagonal normalization/court clamping, Taya line restriction, required outbound-before-return progression, tag radius, and result evaluation.

## Relay

Relay is intentionally not a dependency of this first LAN milestone. Adding internet join codes later requires a linked Unity Cloud project plus Authentication and Relay service configuration/credentials. The transport-facing UI and gameplay authority are isolated so a Relay connection workflow can replace only the connection setup.
